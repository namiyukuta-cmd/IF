# IF シナリオ作成仕様

この文書は、IFで既存シナリオをゲーム化するとき、およびAIに新規シナリオを作らせるときの共通仕様です。

## 基本方針

- `DD.html` はゲームを表示する共通の器として維持し、シナリオ本文や固有データを直接書き込まない。
- シナリオは `scenarios/<scenario-id>/` 以下に置く。
- 共通D&Dデータに存在するアイテム・モンスター・ルールは複製せず、IDで参照する。
- シナリオ固有のNPC・マップ・アイテム・モンスター・報酬だけをシナリオ側へ置く。
- シナリオが増えてもHTML本体へ大量のデータを読み込ませず、選択されたシナリオだけを遅延読み込みする。

## クエスト基本情報

各クエストには、シナリオ本文・シーンデータとは別に、クエスト一覧で使う基本情報を持たせる。

最低限、次を記録する。

- `id`
- `title`
- `minLevel`
- `maxLevel`
- `recommendedLevel`（元資料に明記がある場合）
- シナリオデータへの入口

既存シナリオをゲーム化する場合は、元資料に書かれている想定レベル・推奨レベルをそのまま使用する。資料にない場合は勝手に断定せず、未設定またはAI推定であることを明示する。

クエスト一覧には想定レベルを表示する。推奨レベルが別途明記されている場合は、それも表示する。

例：`想定Lv.7〜10 / 推奨Lv.8`

## 既存シナリオをゲーム化する流れ

1. 元シナリオを最後まで読む。
2. クエストの想定レベル・推奨レベルを確認する。
3. 内容を次の6分類で整理する。
   - 大枠
   - マップ
   - アイテム
   - モンスター
   - 報酬
   - 分岐・状態
4. 全シーンを順番に抽出する。
5. 各シーンについて次を整理する。
   - scene id
   - 場所
   - 表示本文
   - 登場NPC
   - 選択肢
   - 判定・セーヴ
   - 必要アイテム
   - 状態条件
   - 状態変化
   - 戦闘
   - 次のscene
6. `scenario.js` と `scenes.js` を中心にゲーム用データへ変換する。
7. 必要に応じて `maps.js`、`npcs.js`、`items.js`、`monsters.js`、`rewards.js` に分離する。小規模シナリオでは無理に分割しなくてよい。
8. シナリオローダーへ接続する。
9. 全分岐を検査し、到達不能scene、存在しないnext、未定義ID、未定義状態がないか確認する。
10. 最初から最後まで実際に遊べる状態にする。途中で「後で実装」「次工程」などの停止点を残さない。

## AIが新規シナリオを作る流れ

新規シナリオでは、中間のスプレッドシートは必須ではない。最初から以下を構造化して作る。

- 想定レベル
- 推奨レベル（必要なら）
- 大枠
- マップ
- アイテム
- モンスター
- 報酬
- 分岐・状態
- 全scene

そのままゲーム用JSへ変換し、既存シナリオと同じ検査を行う。

## スプレッドシートの役割

スプレッドシートはシナリオ内容の整理・確認用の中間資料として使用する。

共通のゲーム仕様やAIが毎回守るルールはスプレッドシートではなく、このリポジトリ内の仕様書を基準とする。

## 推奨ファイル構成

```text
scenarios/
  scenario-list.js
  <scenario-id>/
    scenario.js
    scenes.js
    maps.js       # 必要な場合のみ
    npcs.js       # 必要な場合のみ
    items.js      # 必要な場合のみ
    monsters.js   # 必要な場合のみ
    rewards.js    # 必要な場合のみ
```

## 判定の共通仕様

- 判定を選択しただけで自動的にd20を振らない。
- プレイヤーが判定内容を選んだあと、明示的な「d20を振る」操作を挟む。
- 判定結果は成功・失敗、出目、修正値、DCが分かるように表示する。
- シナリオ本文に有利・不利・自動成功・自動失敗などの条件がある場合は状態と所持品を参照する。

## 戦闘の共通仕様

- 戦闘sceneは敵データを表示して停止してはいけない。
- 戦闘開始、イニシアチブ、手番、攻撃、ダメージ、勝敗、戦闘後の次sceneまで接続する。
- 元シナリオに戦闘マップがある場合は、そのマップを使用する。
- スマホ縦画面で、戦闘に必要なHP・敵・ログ・操作ができるだけ1画面内に収まるようにする。

## マップの共通仕様

- 元シナリオに画像マップがある場合は画像を接続する。
- 画像マップがない場所は、勝手に地図画像を作らず「専用画像マップなし」と扱う。
- 発見済みの場所・マップだけをプレイヤーのマップ画面へ表示する。
- マップ表示はスマホで過剰な縦スクロールにならない大きさにする。

## クエストの状態

最低限、次の状態を扱う。

- available: 未開始
- active: 進行中
- completed: 完了
- failed: 失敗

完了済みクエストはクエスト一覧で「済」と表示し、再選択できない。

## 死亡・クエスト失敗時

プレイヤーキャラクターが死亡し、クエストが失敗した場合はゲームを操作不能のまま止めない。

必ず次の2択を表示する。

1. `TOPに戻る`
2. `このクエストを最初から`

### TOPに戻る

- `DD_top.html` へ戻る。

### このクエストを最初から

キャラクターそのものは維持し、現在のクエストだけを初期化する。

再開前に必ず以下を行う。

- `HP = maxHP`
- 死亡セーヴ成功数・失敗数をリセット
- `pendingCombat` を削除
- 対象クエストの `scenarioProgress` を開始地点へ戻す
- 対象クエストの `scenarioStates` を初期値へ戻す
- 対象クエストの失敗状態を解除
- クエスト開始sceneから再開

他のキャラクターデータ、所持品、装備、クラス、能力値などは消さない。

## クエスト完了時

- 完了状態を保存する。
- 報酬を反映する。
- クエスト一覧では「済」と表示して押せなくする。
- ゲーム全体は終了させず、TOPへ戻る・他のクエストを選ぶなど次の操作が可能な状態を維持する。

## AIへの最短指示

既存シナリオの場合は、次の指示を基準にする。

> `docs/scenario-spec.md` の仕様に従って、このシナリオをIFで最初から最後まで遊べる形にゲーム化してください。

新規シナリオの場合は、次の指示を基準にする。

> `docs/scenario-spec.md` の仕様に従って、新しいシナリオを設計し、そのままIFで最初から最後まで遊べるゲームデータとして実装してください。
